# 插件功能增强参考设计

本文基于 `docs/cssjs_一些自用的_css_和配套_js.md` 梳理可转化为“粉刷匠”插件能力的样式项，并设计其在插件中的展示形式。目标不是把零散 CSS 直接复制进插件，而是抽象成可预览、可开关、可配置、可导入导出的样式模块。

## 现有插件能力边界

当前插件以“样式目标 + 前景色/背景色通道 + CSS 注入”为核心，已覆盖标题、加粗、引述块、行内代码、高亮、代码块和列表等正文元素。适合优先扩展的方向是继续围绕文档编辑区的可见样式增强；涉及全局 UI、菜单、文档树和工具栏的能力需要单独分组，避免影响思源主界面的稳定性。

## 功能分组设计

### 1. 正文块样式

参考项包括段落块高亮、折叠块样式、分割线、圆角图片、表格样式、编辑区背景色。

建议新增“正文块”分组，提供卡片式开关与轻量参数：

- 段落悬停高亮：开关、背景色、阴影强度、过渡速度。
- 折叠块提示：开关、条纹/纯色模式、边框色、透明度。
- 图片圆角：开关、圆角半径。
- 表格增强：开关、表头背景、边框粗细、单元格内边距。
- 编辑区背景：开关、背景色，提示该项影响全局阅读和编辑区域。

展示形式：在基础粉刷旁新增一级标签页“正文块”，每个功能以紧凑设置卡展示，卡片顶部有启用开关，卡片内部放颜色圆点、滑块和小型预览。

### 2. 行内元素样式

参考项包括块引用链接、超链接、下划线、删除线、标记、高亮、行内代码、PDF 标注。

建议扩展现有 `StyleTarget`，或新增“行内元素”分组：

- 超链接：常态色、悬停色、下划线样式（无/实线/虚线）。
- 块引用与文件标注：字色、背景、字重、下划线、图标前缀开关。
- 下划线：样式选择（实线/虚线/波浪线）、颜色、粗细。
- 删除线：颜色、粗细、线型。
- 标记文本：背景色、底部强调线、挖空模式。
- 行内代码：字色、背景色、圆角、内边距。

展示形式：保留当前颜色浮层，但在浮层中增加“高级”折叠区。普通用户只改颜色，高级用户展开后调整线型、粗细、圆角、字重等属性。

### 3. 标题与列表样式

参考项包括禁用标题编号、标题间距、标题颜色、标题符号、竖道标题标志、标题下划线、层次子弹线、自定义无序/有序列表、任务列表状态、折叠列表提示。

建议新增“结构样式”分组：

- 标题装饰：无、左竖线、下划线、符号前缀。
- 标题间距：H1-H6 分别或统一调整上下间距。
- 标题编号：显示/隐藏，并提供对大纲和文档树的联动提示。
- 列表层次线：开关、线色、线宽。
- 无序列表圆点：按层级配置颜色和形状。
- 有序列表序号：序号背景、圆角、位置偏移。
- 任务列表：完成态透明度、勾选框边框、悬停色。

展示形式：使用“标题 / 列表”二级分段控件。标题部分提供 H1-H6 纵向预览；列表部分提供三层嵌套列表预览。

### 4. 引用与关系提示

参考项包括引述块边框竖线、被引用块两角实线框、右上角引用次数、引用搜索展示、反链与提及面板固定文档名称。

建议将其设计为“引用关系”分组：

- 引述块外观：边框、竖线、圆角、内边距。
- 被引用块角标：开关、角标颜色、角标长度。
- 引用次数徽标：背景色、悬停放大、发光强度。
- 引用搜索菜单：候选项高度、圆角、悬停背景、最大高度。
- 反链/提及固定标题：开关，作为全局 UI 影响项标注风险。

展示形式：功能卡右上角增加风险标签：`正文安全`、`全屋改造`、`全局 UI`。引用搜索和反链面板属于全局 UI，默认折叠在“实验性”区域。

### 5. 文档外观与导航 UI

参考项包括文件标题放大、头图头标、头图下方文档标签、文档树彩色分块、大纲/文档树流动布局、大纲数字标志。

建议新增“文档外观”分组，但作为第二阶段功能：

- 文档标题：字号、占位提示色。
- 头图：图片圆角、左右边距、操作按钮显示策略。
- 文档图标：尺寸、悬停背景、对齐方式。
- 文档标签：标签圆角、颜色集、关闭按钮悬停显示。
- 文档树彩色分块：开关、五色循环色板、间距。
- 大纲/文档树布局：流式布局和数字标志需谨慎处理，默认不启用。

展示形式：新增“全局外观”页签，页签顶部显示说明：这些设置可能影响编辑器外壳和侧栏，建议逐项启用。

### 6. 菜单与浮层优化

参考项包括块标动画、工具条样式、表情面板、斜杠菜单、写味多行搜索样式、插件按钮样式、放大工具栏按钮。

建议作为“交互浮层”实验分组：

- 块标动画：移动过渡、悬停背景。
- 文字工具条：阴影、按钮尺寸、当前项颜色。
- 斜杠菜单：宽度、多列、最大高度、项间距。
- 表情面板：宽度、表情尺寸、项间距。
- 插件按钮和顶栏按钮：影响范围大，默认只提供 CSS 模板导出，不直接注入。

展示形式：实验分组使用独立开关“启用实验性 UI 样式”。未开启时只展示预览和说明；开启后才显示具体选项。

## 插件界面信息架构

建议将当前单页基础粉刷升级为三层结构：

1. 顶部模式切换：`正文样式`、`结构样式`、`全局外观`、`实验性`。
2. 中部目标卡片：沿用当前对象卡片，但按分组展示不同目标。
3. 右侧或浮层编辑器：保留颜色选择器，并根据目标类型动态展示高级控件。

在窄屏 Dock 中，顶部模式切换使用横向滚动 segmented control；目标卡仍保持两列或单列响应式布局。每个功能卡应包含启用开关、简短名称、风险标签和预览区域，不在界面中堆放长说明。

## 数据模型建议

现有 `StyleRule` 只有颜色、字重、斜体和装饰字段，后续可扩展为两类配置：

- `targetProfile`：面向正文元素的可导入导出样式，如标题、链接、标记、表格。
- `featureProfile`：面向功能模块的开关和参数，如段落悬停、文档树分块、斜杠菜单。

示例结构：

```ts
interface FeatureStyleConfig {
  enabled: boolean;
  values: Record<string, string | number | boolean>;
}
```

CSS 生成应改为模块化：每个功能提供 `buildCss(config)`，最终由运行时合并注入。这样可以避免一个巨大的样式拼接函数，也方便单元测试。

## 优先级建议

第一阶段优先实现低风险、正文内可预览能力：

1. 行内元素增强：链接、下划线、删除线、行内代码、标记。
2. 正文块增强：段落悬停、引述块、图片圆角、表格。
3. 标题与列表增强：标题装饰、列表层次线、任务列表状态。

第二阶段再实现影响编辑器外壳的能力：

1. 文档标题、头图、文档标签。
2. 引用搜索、反链面板、文档树彩色分块。
3. 工具条、斜杠菜单、表情面板等实验性 UI。

## 测试与验收

新增能力应覆盖以下测试：

- 配置归一化：缺省值、非法值、旧版本数据兼容。
- CSS 生成：每个功能开关启用/关闭时输出正确。
- 预览样式：卡片预览能反映颜色、线型、圆角等关键参数。
- 导入导出：新增配置随样式包保存和恢复。
- 风险隔离：实验性功能关闭时不输出对应 CSS。

验收标准：用户可以在插件中按分组找到样式目标，启用后立即看到效果，关闭后样式完全移除；正文样式和全局 UI 样式在界面上有明确区分。
